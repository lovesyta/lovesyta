# 사랑의 연탄천사 — 봉사신청 게시판 백엔드

프론트엔드(웹사이트)와 봉사신청 게시판이 하나의 Node.js 서버로 함께 실행됩니다.

- `public/index.html` — 메인 홈페이지
- `public/about.html` — 연탄천사 소개 (단체소개 / 인사말 / 조직도 / 오시는 길 탭, 글+사진 편집)
- `public/donate.html` — 후원하기 (연탄 후원 / 조손가정 생계지원 / 저소득층 청소년 지원 / 기부금 영수증 신청 탭, 글+사진 편집)
- `public/volunteer.html` — 봉사신청 전용 페이지 (봉사일정 캘린더 + 봉사신청 게시판 + 글쓰기)
- `public/news.html` — 연탄천사 소식 (단체소식 / 언론보도 게시판 — 관리자만 글쓰기 가능)
- `public/community.html` — 커뮤니티 (공지사항 게시판(관리자만 글쓰기) / 문의하기 게시판(누구나 글쓰기))
- `server.js` — 봉사신청 게시글을 저장·조회하는 API 서버
- `data/posts.json` — 봉사신청 게시글이 저장되는 파일
- `data/articles.json` — 공지사항/단체소식/언론보도/문의하기 게시글이 저장되는 파일
- `data/content.json` — 소개/후원 페이지의 편집 가능한 글·사진이 저장되는 파일

헤더/푸터 메뉴는 모든 페이지에서 동일하며, 각 항목을 누르면 이제 홈페이지 안에서
스크롤 이동하는 대신 위 5개의 독립된 페이지로 이동합니다. 하위 메뉴(예: "언론보도")를
누르면 해당 페이지로 이동한 뒤 그 탭이 바로 열립니다.

about/donate 페이지는 탭과 레이아웃만 만들어둔 상태이고, 안의 내용은 비어 있습니다
("콘텐츠 준비 중입니다" 표시) — 관리자가 로그인해서 언제든 글과 사진을 채워 넣을 수 있습니다.
공지사항/단체소식/언론보도/문의하기는 게시판 형식으로 바뀌어서, 목록에서 글을 클릭하면
제목·작성자·작성일·조회수와 함께 사진과 본문이 있는 상세 화면으로 열립니다.

## 1. 로컬에서 실행해보기

준비물: [Node.js](https://nodejs.org) 18버전 이상

```bash
cd backend
npm install
npm start
```

터미널에 아래처럼 뜨면 정상 실행된 것입니다.

```
사랑의 연탄천사 서버가 실행 중입니다: http://localhost:3000
```

- 홈페이지: `http://localhost:3000`
- 봉사신청 게시판: `http://localhost:3000/volunteer.html`

"글쓰기"를 누르면 스크린샷과 동일한 항목(제목/비밀글 옵션/작성자/비밀번호/이름·단체명/
휴대전화번호/비상연락처/희망날짜/인원/개인정보 동의)으로 신청서를 작성할 수 있고,
등록한 내용은 실제로 `data/posts.json` 파일에 저장됩니다.
같은 서버에 접속한 모든 사람이 같은 목록을 보게 되고, 8초마다 자동으로 새 글을 반영합니다.

## 2. 비밀글 기능

- 글쓰기 시 "비밀글" 체크(기본 체크됨)를 하면 비밀번호를 함께 등록합니다.
- 게시판 목록에는 제목·작성자(예: 김\*\*)·작성일·조회수만 보이고,
  이름/단체명, 휴대전화번호, 비상연락처, 희망날짜, 인원 등 개인정보는 목록에 절대 노출되지 않습니다.
- 비밀글을 클릭하면 비밀번호 확인 창이 뜨고, 비밀번호가 맞아야 개인정보가 담긴 상세 내용이 보입니다.
- 비밀글이 아닌 경우 클릭 시 바로 상세 내용이 보입니다.
- **관리자로 로그인되어 있으면** 비밀번호 확인 창 없이 모든 비밀글을 바로 클릭 한 번으로 열어볼 수 있습니다.
  (봉사일정 탭에서 한 번 로그인해두면, 게시판 탭에서도 자동으로 적용됩니다.)

⚠️ 보안 참고: 현재 비밀번호는 데모 수준으로 평문 비교합니다. 실제 운영 서비스로 쓰신다면
`server.js`에서 bcrypt 등으로 반드시 해시 처리해 주세요.

## 3. 콘텐츠(글/사진) 편집 — 관리자 전용 (소개/후원 페이지)

`about.html`(연탄천사 소개), `donate.html`(후원하기) 2개 페이지의 각 탭에는
관리자만 볼 수 있는 "편집" 버튼이 있습니다.

- 페이지 상단(탭 아래)의 "관리자이신가요? 로그인"으로 로그인하면, 모든 탭에 "편집" 버튼이 나타납니다.
  (봉사일정 탭에서 이미 로그인했다면 다른 페이지에서도 자동으로 로그인 상태가 유지됩니다.)
- "편집"을 누르면 글 내용을 쓰는 칸과 "사진 추가" 버튼이 나옵니다. 사진은 여러 장 한 번에 올릴 수 있고,
  올린 사진은 작은 썸네일로 보이며 ✕ 버튼으로 낱개 삭제할 수 있습니다.
- "저장"을 누르면 실제로 `data/content.json` 파일에 저장되어, 모든 방문자에게 그대로 보입니다.
- 아직 아무 내용도 저장하지 않은 탭은 지금처럼 "콘텐츠 준비 중입니다" 안내만 보입니다.

⚠️ 참고: 사진은 별도 저장소 없이 파일 안에 텍스트로 함께 저장되는 방식이라, 사진 수가 아주 많아지면
파일이 커집니다. 사진을 아주 많이 쓸 계획이라면 나중에 이미지 전용 저장소(S3 등)로 옮기는 걸 권장합니다.

## 4. 공지사항 / 단체소식 / 언론보도 / 문의하기 게시판

`community.html`(공지사항, 문의하기)과 `news.html`(단체소식, 언론보도)의 4개 탭은
봉사신청 게시판과 같은 방식(목록 → 글쓰기 → 상세보기)으로 동작합니다.

- **공지사항 / 단체소식 / 언론보도**: 관리자만 글을 쓸 수 있습니다. 관리자로 로그인하면
  "글쓰기" 버튼이 나타나고, 제목·내용·사진(여러 장)·출처 URL(언론보도 기사 링크 등)을 입력해 등록합니다.
  일반 방문자는 목록을 보고 클릭해서 읽을 수만 있습니다.
- **문의하기**: 누구나 글을 쓸 수 있습니다. 이름·제목·내용을 입력하고, "비밀글"(기본 체크됨)로 설정하면
  비밀번호를 입력한 사람이나 관리자만 상세 내용을 볼 수 있습니다.
- 목록에서 글을 클릭하면 제목, 작성자·작성일·조회수, 사진, 본문, (있다면) 출처 링크가 있는
  상세 화면이 열립니다. 관리자로 로그인한 상태라면 상세 화면 아래에 "이 글 삭제" 버튼도 보입니다.
- 게시글이 10개를 넘으면 봉사신청 게시판과 동일하게 페이지 번호가 자동으로 생깁니다.

`donate.html`의 "기부금 영수증 신청" 탭도 봉사신청 게시판과 같은 방식으로 바뀌었습니다.
누구나 글을 쓸 수 있고, 성명·연락처·이메일·기부일자·기부금액 같은 개인정보가 들어가기 때문에
모든 신청은 **항상 비밀번호로 보호**됩니다(별도 "비밀글" 체크 없이 항상 적용). 목록에는 제목과
마스킹된 작성자(예: 김\*\*)만 보이고, 클릭 후 비밀번호를 입력하거나 관리자로 로그인해야만
성명·연락처·이메일·기부일자·기부금액이 담긴 상세 내용을 볼 수 있습니다.

## 5. 공지 상단 고정 (모든 게시판 공통)

관리자가 **공지사항 / 단체소식 / 언론보도**에 글을 쓸 때 "전체 게시판 상단에 공지로 고정"을
체크하면, 그 글이 사이트 안의 **모든 게시판**(공지사항, 단체소식, 언론보도, 문의하기, 봉사신청,
기부금 영수증 신청) 목록 맨 위에 📌 표시와 함께 공통으로 나타납니다. 최대 5개까지 보이고,
가장 최근에 고정한 글이 위로 옵니다.

- 글쓰기 시 체크하거나, 이미 쓴 글의 상세 화면에서 "전체 게시판 상단에 공지로 고정" / "고정 해제"
  버튼으로 나중에 바꿀 수 있습니다(관리자로 로그인한 상태에서만 보입니다).
- 문의하기·봉사신청·기부금영수증 게시판에서는 고정 공지를 새로 만들 수는 없고, 다른 곳에서
  고정한 공지가 보이기만 합니다. 그 글을 클릭하면 원래 게시판의 해당 페이지로 이동해서 바로 열립니다.
- 고정 공지는 원래 게시판의 일반 목록에도 그대로 남아 있습니다(중복 표시되는 게 정상입니다 —
  흔히 보는 게시판의 "공지" 고정 방식과 같습니다).

## 6. 페이지네이션 / 검색

- 게시글이 10개를 넘으면 목록 아래에 페이지 번호(처음/«/1~10/»/마지막)가 자동으로 생깁니다.
- "전체" 상단 숫자는 현재 검색 결과 기준 건수를 보여줍니다.
- 하단 검색창에서 "전체/제목/작성자" 중 선택 후 검색어를 입력하면 목록이 필터링됩니다.
- 새 글을 등록하면 검색어와 페이지가 초기화되어 방금 등록한 글이 1페이지 맨 위에 바로 보입니다.

## 7. 봉사일정 캘린더 & 관리자 등록 방법

`volunteer.html`의 "봉사일정" 탭이 달력으로 바뀌었습니다. 좌우 화살표로 월을 이동할 수 있고,
날짜 칸에 등록된 일정이 표시됩니다. **일정 등록/삭제는 관리자(운영자)만 할 수 있습니다.**

### 관리자 키 설정 (최초 1회, 서버 운영자가 할 일)

기본값으로 두면 다른 사람도 추측할 수 있으므로, 서버를 실행하기 전에 나만 아는 값으로 바꿔주세요.

```bash
# Mac / Linux
ADMIN_KEY="나만아는비밀값" npm start

# Windows (PowerShell)
$env:ADMIN_KEY="나만아는비밀값"; npm start
```

Render 같은 곳에 배포할 때는 대시보드의 "Environment Variables" 설정에 `ADMIN_KEY` 키로
같은 값을 등록하면 됩니다.

### 실제로 일정을 등록하는 방법 (관리자 본인이 할 일)

1. `volunteer.html`의 "봉사일정" 탭을 엽니다.
2. 달력 오른쪽 위 "관리자이신가요? 로그인"을 누르고, 위에서 설정한 관리자 키를 입력합니다.
3. 로그인에 성공하면 각 날짜 칸에 "+ 일정추가" 버튼이 나타납니다. 원하는 날짜에서 버튼을 눌러
   제목과 모집 상태(모집중/모집마감)를 입력하고 등록합니다.
4. 등록한 일정 옆의 "✕"를 누르면 삭제할 수 있습니다(관리자로 로그인된 상태에서만 보입니다).
5. 한 번 로그인하면 그 브라우저에는 키가 저장되어 있어 다음에 다시 입력할 필요가 없습니다.
   다른 사람과 같이 쓰는 컴퓨터라면 확인 후 "로그아웃"을 눌러주세요.

관리자가 아닌 일반 방문자에게는 로그인 버튼만 보이고, "+ 일정추가"나 삭제 버튼은 전혀 보이지 않습니다.

## 8. 실제로 인터넷에 배포하기

지금은 내 컴퓨터에서만 접속되므로, 실제 도메인으로 서비스하려면 서버 호스팅이 필요합니다.
아래 서비스들은 무료 요금제로 시작할 수 있고, 이 프로젝트 구조(Node.js + Express)를 그대로 지원합니다.

- **Render** (render.com) — `backend` 폴더를 GitHub에 올린 뒤 "Web Service"로 연결, Build Command `npm install`, Start Command `npm start`
- **Railway** (railway.app) — GitHub 저장소 연결만으로 자동 배포
- **Cafe24 / 가비아 등 국내 Node.js 호스팅** — 이미 도메인이 있다면 이쪽이 편할 수 있습니다

배포 후에는 실제 주소(예: `https://yeontan-angel.onrender.com`)로 웹사이트와 게시판이 함께 열립니다.
프론트엔드 코드는 같은 서버의 `/api/posts`를 상대경로로 호출하도록 되어 있어서,
배포 주소가 바뀌어도 코드를 따로 수정할 필요가 없습니다.

## 9. 데이터를 진짜 데이터베이스로 옮기고 싶다면

지금은 `data/posts.json` 파일 하나에 글이 저장됩니다. 소규모 단체 홈페이지 수준에서는 충분하지만,
글이 아주 많아지거나 여러 대의 서버로 운영하게 되면 SQLite나 MySQL 같은 DB로 옮기는 것이 좋습니다.

`server.js` 안의 `readData()` / `writeData()` 두 함수만 DB 연결 코드로 바꾸면 되고,
API 경로와 프론트엔드 코드는 그대로 두셔도 됩니다.

## 10. API 요약

| Method | 경로 | 설명 |
|---|---|---|
| GET | `/api/posts` | 봉사신청 목록 조회 (최신순, 개인정보 필드 미포함) |
| POST | `/api/posts` | 봉사신청 등록 — body: `{ title, secret, author, password, orgName, phone, emergency, hopeDate, headcount }` |
| PATCH | `/api/posts/:id/view` | 상세 조회(개인정보 포함) — body: `{ password }` (비밀글일 때만 필요, 관리자 키가 있으면 생략 가능) |
| GET | `/api/schedule` | 봉사일정 전체 조회 (누구나 가능) |
| POST | `/api/schedule` | 일정 등록 — 헤더 `x-admin-key` 필요, body: `{ date, title, status }` |
| DELETE | `/api/schedule/:id` | 일정 삭제 — 헤더 `x-admin-key` 필요 |
| GET | `/api/content` | 페이지 콘텐츠(글/사진) 전체 조회 (누구나 가능) |
| POST | `/api/content` | 콘텐츠 등록/수정 — 헤더 `x-admin-key` 필요, body: `{ key, text, images }` |
| GET | `/api/articles?board=X` | 게시판(notice/news/press/contact) 글 목록 조회 (누구나 가능) |
| POST | `/api/articles` | 글 등록 — notice/news/press는 헤더 `x-admin-key` 필요, contact는 누구나. body: `{ board, title, author, content, images, sourceUrl, secret, password, pinned }` (pinned는 notice/news/press만 유효) |
| PATCH | `/api/articles/:id/view` | 글 상세(본문/사진 포함) 조회 — body: `{ password }` (문의하기 비밀글일 때만 필요, 관리자 키가 있으면 생략 가능) |
| GET | `/api/pinned` | 상단 고정된 공지 목록 조회 (모든 게시판 공통, 최대 5개, 누구나 가능) |
| PATCH | `/api/articles/:id/pin` | 고정/고정 해제 — 헤더 `x-admin-key` 필요, body: `{ pinned }`, notice/news/press 글만 가능 |
| DELETE | `/api/articles/:id` | 글 삭제 — 헤더 `x-admin-key` 필요 |
| GET | `/api/receipts` | 기부금 영수증 신청 목록 조회 (개인정보 필드 미포함) |
| POST | `/api/receipts` | 신청 등록 — body: `{ title, author, password, name, phone, email, donationDate, amount }` (항상 비밀번호 필요) |
| PATCH | `/api/receipts/:id/view` | 상세 조회(개인정보 포함) — body: `{ password }` (관리자 키가 있으면 생략 가능) |
| POST | `/api/admin/verify` | 관리자 키 확인 — 헤더 `x-admin-key`가 맞는지만 검사 |

작성자명은 서버에서 자동으로 "김\*\*" 형태로 마스킹되어 저장·응답됩니다.
